# 栽培観察レポート（技術科・生物育成）— Word 入力版

`scripts/make_report.py` が、**生徒が Word で記入して提出できる** .docx を1つ作ります。すべて **A4 縦・1日1枚**。

| ページ | 内容 |
|---|---|
| 表紙 | 「〈作物名〉の栽培観察レポート」、年・組・番、名前、観察・栽培期間（開始日〜終了日）、観察日数、記入のしかた |
| 観察日記（月〜金の各日） | 第○日目・日付・曜日／天気・気温・観察時刻／**写真欄**／**一番大きい株の背丈（cm）**・**葉の枚数（枚）**・前回からの変化／今日した手入れ（チェック）／**観察・手入れの記録と考察** |
| 収穫後のまとめ | 収穫日・収穫量・最後の背丈・葉の枚数・栽培日数／収穫物の写真欄／育ててわかったこと・工夫したこと・改善点・生活や社会とのつながり |

## 生徒が Word でできること

記入欄はすべて Word の **コンテンツ コントロール** です。表の形を崩さずに入力できます。

| 欄 | 操作 |
|---|---|
| 年・組・番・名前、数字の欄、その他 | クリックして入力。灰色の案内文字は入力すると消える |
| 年・組・番・名前 | **表紙で1回入れると、全ページのヘッダーに自動で反映**（customXml のデータ連動） |
| 天気 | ▼から選ぶ（晴れ／くもり／雨／雪／晴れ時々くもり／くもり時々雨） |
| 手入れ | □ をクリックするとチェックが入る（☐→☑） |
| 写真欄 | クリックすると「図の挿入」が開き、写真が **枠の大きさに合わせて** 入る。差し替えは右クリック→［図の変更］ |
| 考察・まとめの枠 | 自由に複数行・複数段落で書ける。枠の大きさは固定（1日1枚を保つため）で、はみ出した分は表示されない |
| 収穫日 | カレンダーから選ぶ |

`--print` を付けると、コントロールの代わりに **罫線と空欄の手書き用** を作ります（印刷して配布する場合）。

## 手順

1. **必要な情報を確認する。** 足りないものだけ聞く。
   - 必須：**作物名**、**開始日**、**終了日**（年が無ければ今年として扱う）
   - 任意：学年・組・番号・名前（クラス配布用なら空欄でよい。生徒が表紙で入力する）
   - 任意：除外したい平日（祝日・行事・長期休業など）。祝日は自動では除外しないので、期間内の祝日を確認して `--skip` に入れる
   - 任意：写真フォルダ、手書き用（`--print`）が必要か
2. **スクリプトを実行する。**

   ```bash
   python3 .claude/skills/cultivation-report/scripts/make_report.py \
     --crop ミニトマト --start 2026-05-11 --end 2026-07-17 \
     --skip 2026-07-20 -o ミニトマト_栽培観察レポート.docx
   ```

   | オプション | 意味 |
   |---|---|
   | `--crop` | 作物名（タイトルとヘッダーに入る） |
   | `--start` / `--end` | 観察・栽培期間 `YYYY-MM-DD`。この間の **月〜金だけ** が1日1ページになる |
   | `--grade` `--klass` `--number` `--name` | 学年・組・番号・名前を最初から入れておく（省略可） |
   | `--skip` | 除外する平日をカンマ区切りで |
   | `--photos` | 写真フォルダ。`2026-05-11.jpg`／`20260511.jpg`／`0511.jpg` のように日付を含む名前はその日の写真欄に、`harvest.jpg`（または「収穫」を含む名前）はまとめページに入る（Word 上で差し替え可） |
   | `--print` | 手書き用（罫線つき・入力欄なし）で作る |
   | `--pdf` | LibreOffice（`soffice`）で PDF も作る（確認用・印刷用） |
   | `-o` | 出力ファイル名（省略時は `<作物名>_栽培観察レポート.docx`） |

   依存：`python-docx`、`Pillow`。PDF 化には LibreOffice。
3. **確認する。**
   - `--pdf` を付けて作り、`pdfinfo` のページ数が「表紙1＋観察日数＋まとめ1」と一致すること（1日分が2ページにはみ出していないこと）。
   - 必要なら `pdftoppm -r 60 -png -f 2 -l 2 file.pdf p` で1ページを画像にして見た目を確認する。
   - XML の妥当性は docx スキルの `scripts/office/validate.py file.docx` で確認できる（スキーマ順の誤りは Word で「読み取れない内容」になる）。
   - LibreOffice ではコンテンツ コントロールの連動（表紙→ヘッダー）は再現されない。Word での動作が正。
4. **渡す。** 作成した .docx をユーザーに送り、ページ数・期間・除外した日を一言で伝える。

## 調整するとき

`scripts/make_report.py` の先頭の定数と各関数を編集する。

- 手入れのチェック項目：`CARE_ITEMS`（作物に合わせて「摘果」「人工授粉」などに入れ替え可）
- 天気の選択肢：`WEATHER`
- フォント：`FONT`（既定は Windows 標準の BIZ UDPゴシック）
- 写真欄の高さ・考察の枠の高さ：`day_page()` の `photo_box(doc, 92, …)` と `writing_box(doc, 114, …)`
- まとめの項目：`summary_page()` のリスト

枠を大きくすると1日が2ページにはみ出すことがある。変更したら必ず手順3でページ数を確認する。
